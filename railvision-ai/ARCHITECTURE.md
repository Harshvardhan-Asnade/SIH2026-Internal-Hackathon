# RailVision AI — System Architecture

This document describes the high-level architecture of RailVision AI.

## Overview
RailVision AI is a highly modular, hardware-accelerated computer vision and natural language analytics platform tailored for railway station monitoring.

The system is split into a **Next.js Frontend** and a **FastAPI Backend**, communicating via REST APIs.

## AI Engine Architecture (`ModuleRegistry`)
The core of the system is the `ModuleRegistry`—a singleton orchestrator that manages multiple plug-and-play AI modules.

### Inference Loop
When a video is uploaded, the backend executes the inference loop:
1. **Frame Extraction**: OpenCV reads the video frame-by-frame.
2. **Frame Skipping**: By default, inference is run every N-th frame (configured via `frame_skip`) to cut GPU/CPU processing time by 50-66% while maintaining a smooth 30fps output video.
3. **Module Execution**:
   - `PersonDetectionModule`: Runs YOLO26 to detect people.
   - `CrowdAnalysisModule`: Uses person detections to generate crowd heatmaps, density scores, and panic alerts.
   - `CrimeDetectionModule`: Uses tracks to identify intrusions, loitering, running, and fights.
   - `WorkerMonitoringModule`: Monitors railway staff efficiency and PPE compliance.
4. **Shared Context**: Modules share a `shared_context` dictionary per frame. For example, the `CrowdAnalysisModule` reuses the bounding boxes generated by `PersonDetectionModule`, ensuring YOLO is only executed **once per frame**.

## Enterprise Knowledge Base
Instead of raw detections, the backend automatically generates a structured Knowledge Base after processing:
- `summary.json`: High-level aggregated statistics.
- `timeline.json`: A chronological database of all generated alerts and incidents.
- `objects.json`: Compressed track histories for specific people.
- `events.json`: Semantic graph of scene changes.

## LLM Integration & Context Builder
RailVision AI features an integrated LLM (Qwen 3) that acts as an "AI Master".

1. **Question Router**: User queries are analyzed to determine the category (e.g., "Crowd", "Crime", "Summary").
2. **Context Builder**: The backend dynamically loads only the required JSON files from the Knowledge Base (e.g., loading `crowd.json` and `timeline.json` for a crowd question), completely preventing LLM context-window crashes.
3. **Report Generation**: The LLM responds with high-quality, token-efficient intelligence reports.

## Frontend Optimization
The frontend uses Zustand for state management. State access is deeply optimized using `useShallow` selectors, ensuring heavy UI components (like the sidebar, video player, and analytics dashboard) only re-render when their specific data changes, achieving a steady 60fps even during complex data visualizations.
