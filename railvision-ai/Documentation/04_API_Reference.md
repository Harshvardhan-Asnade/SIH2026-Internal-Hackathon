# API Reference (FastAPI Backend)

The RailVision AI Backend exposes a clean REST API. All heavy processing occurs asynchronously to ensure the event loop remains responsive.

## 1. Video Processing Pipeline

### `POST /upload`
**Purpose**: Upload a raw surveillance video to the server.
**Payload**: `multipart/form-data` containing the video file (MP4, AVI, MOV, MKV).
**Response**: Returns a unique `video_id` which is required for all subsequent pipeline operations.
**Logic**: Validates file size and extension, saves it to the local `uploads/` directory.

### `POST /process`
**Purpose**: Run the modular AI inference engine on an uploaded video.
**Payload**: JSON containing the `video_id`.
**Response**: Returns a `ProcessingResult` JSON containing bounding boxes, alerts, crowd data, and the generated **AI Master Intelligence Report**.
**Logic**: 
- Locates the video via `video_id`.
- Dispatches the inference engine via `asyncio.to_thread` (non-blocking).
- Triggers the Knowledge Base Generator.
- Triggers the Context Builder and queries the LLM for a summary report.

### `GET /result/{video_id}`
**Purpose**: Download the final annotated video.
**Response**: Returns a `video/mp4` stream of the output video with all bounding boxes and HUD elements baked in.

## 2. Analytics & Query Endpoints

### `GET /heatmap`
**Purpose**: Retrieve the latest crowd density heatmap.
**Response**: Returns a `.png` image overlaying crowd hotspots generated by the `CrowdAnalysisModule`.

### `POST /query`
**Purpose**: Query the integrated AI Master with natural language.
**Payload**: JSON containing the `query` (string) and an optional `video_id`.
**Response**: Returns a detailed intelligence response generated by Qwen 3 based on the specific Knowledge Base files.

---

## 3. System Status

### `GET /health`
**Purpose**: Liveness and readiness probe for orchestration/Docker.
**Response**: Returns the system status, device mapping (CUDA/MPS/CPU), version, and an array of currently active AI modules in the `ModuleRegistry`.
